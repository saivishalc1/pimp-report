# Admin CRM — setup

The dashboard lives at **`/admin.html`**. Until you do the steps below it runs in
**preview mode**: it shows only what your own browser recorded, and no visitor
data is captured anywhere. The dashboard says so on screen, so preview numbers
can never be mistaken for real ones.

This site is static (GitHub Pages), so there is no server to run. Supabase
supplies the database, the API and the login, and the browser talks to it
directly. Free tier is enough.

---

## 1. Create the project

1. Sign up at <https://supabase.com> and create a project.
2. Open **Project Settings → API** and copy:
   - **Project URL** — `https://xxxxxxxx.supabase.co`
   - **anon public** key

## 2. Create the tables

Open **SQL Editor** in Supabase, paste all of this, and run it.

> Read the policies before running. They are what stop the public key from
> reading your customers.

```sql
-- ── tables ────────────────────────────────────────────────────────────────
create table if not exists public.leads (
  id          bigint generated by default as identity primary key,
  created_at  timestamptz not null default now(),
  name        text,
  email       text,
  phone       text,
  message     text
);

create table if not exists public.subscribers (
  id          bigint generated by default as identity primary key,
  created_at  timestamptz not null default now(),
  email       text
);

create table if not exists public.events (
  id          bigint generated by default as identity primary key,
  created_at  timestamptz not null default now(),
  session     text,
  kind        text,
  label       text,
  meta        jsonb default '{}'::jsonb
);

create index if not exists events_created_idx on public.events (created_at desc);
create index if not exists events_kind_idx    on public.events (kind);

-- ── row level security ────────────────────────────────────────────────────
-- The anon key ships inside the public page, so anyone can read it. These
-- policies are the whole security model: anon may INSERT, and only a
-- signed-in user may SELECT. Without them your customer list would be
-- readable by anybody who views source.
alter table public.leads       enable row level security;
alter table public.subscribers enable row level security;
alter table public.events      enable row level security;

create policy "anon can submit leads"       on public.leads
  for insert to anon with check (true);
create policy "anon can subscribe"          on public.subscribers
  for insert to anon with check (true);
create policy "anon can record events"      on public.events
  for insert to anon with check (true);

create policy "signed-in can read leads"       on public.leads
  for select to authenticated using (true);
create policy "signed-in can read subscribers" on public.subscribers
  for select to authenticated using (true);
create policy "signed-in can read events"      on public.events
  for select to authenticated using (true);
```

## 3. Create your admin login

**Authentication → Users → Add user.** Use a real email and a strong password.
That is the account you sign into `/admin.html` with.

Then in **Authentication → Providers → Email**, turn **off** "Enable sign-ups"
so nobody else can create an account against your project.

## 4. Paste the keys into both files

Two places, same two values.

`index.html` — in the `CFG` block near the top of the script:

```js
cloud: { url:"https://xxxxxxxx.supabase.co", key:"eyJhbGciOi..." },
```

`admin.html` — at the top of its script:

```js
const CLOUD = { url:"https://xxxxxxxx.supabase.co", key:"eyJhbGciOi..." };
```

Commit and push. The badge in the dashboard header flips from
**Preview — local only** to **Live**, and the sign-in screen appears.

## What gets recorded

| Kind | When | Shown as |
|---|---|---|
| `session` | once per tab, with referrer + device bucket | Visits over time, sources, devices |
| `section` | a section scrolls into view | Sections read |
| `chat` | every assistant question, with whether it was answered | Most asked / Asked but not answered |
| `nft` | an NFT is opened | NFTs opened |
| `outbound` | a click to Rarible, Patreon, TikTok, YouTube, phone | Clicks off the site |
| `form` | a contact or newsletter submission | Leads / Subscribers |

**Asked but not answered** is the panel worth checking weekly. Every row is a
question a real visitor asked that the site could not answer — the most direct
list of what to write next.

No cookies and no third-party analytics. The session id is random, stored in
`sessionStorage`, and gone when the tab closes, so it cannot follow anyone
between sites or visits.

## Things worth knowing

**The anon key is public by design.** It sits in the page source. It is safe
*only* because of the RLS policies in step 2 — insert-only for anon. Do not paste
the `service_role` key into either file; it bypasses RLS entirely.

**`/admin.html` is not a secret URL.** It is `noindex` and disallowed in
`robots.txt`, but anyone can open it. The protection is the Supabase login: with
no valid token the data requests come back empty. In preview mode there is no
login because there is nothing to protect — only your own browser's events.

**Preview mode is per-browser.** Events live in `localStorage`, so what you see
on your laptop is not what you see on your phone, and neither is what visitors
did. Only step 4 makes the numbers real.

**Retention.** Nothing is deleted automatically. If `events` grows large, trim it:

```sql
delete from public.events where created_at < now() - interval '180 days';
```

**Privacy.** Leads hold names, emails, phone numbers and messages that people
gave you deliberately. Chat logs hold whatever visitors typed. If you publish a
privacy policy, both belong in it.
